2. Think
LLM Call — completeStream()
ProviderPool → executor or planner tier
SSE streaming → parseSSEStream()
Text deltas → STREAM_CHUNK to side panel (real-time)
Tool call deltas → accumulated across SSE chunks

Think-tag handling:
• completeStream() returns raw content (think blocks preserved)
• complete() strips via stripThinkTags() (planner needs clean JSON)
• History stores raw — reasoning chain continuity
• Loop derives cleanContent for logic/logging
→
3. Act
Tool Execution — executeTurns()
Parallel batch — all non-sequential tools via Promise.all
Sequential — navigate, done, escalate, go_back (one at a time)
Batch snapshot refresh — one read_page after all tools (not per-tool)

Pre-execution checks:
• Workspace isolation — is tab in active workspace?
• Discovered tag IDs — validate dynamically-created tags
• Approval gate — if requireApprovals and HIGH risk tool
• Stagnation check — snapshot fingerprint change since last turn?
Turn Lifecycle (per iteration)
while (isRunning && turns < MAX_TURNS) {
// 1 messages = context.buildPrompt()
// 2 status = THINKING; broadcast AGENT_STATUS
// 3 response = await llm.completeStream({ messages, tools }, delta => sendStreamChunkToUI(delta))
// 4 rawContent → history; cleanContent → logic
// 5 if (response.tool_calls) {
// 6 status = ACTING; broadcast AGENT_STATUS
// 7 await executeTurn(response.tool_calls) // parallel or serial based on SEQUENTIAL_TOOLS
// 8 validateElementIds(toolCalls, currentSnapshot) // grounding_mismatch detection
// 9 await refreshSnapshot() // single batch after all tools
// 10 if (toolName === 'done') → handleDone() → completion kernel
// 11 checkStagnation(snapshotFingerprint) // nudge→escalate→give-up
// 12 } else { /* text-only: escalate or finish */ }
// 13 sessionMetrics updated; broadcast every 3 turns

Orchestrator Phase 6 — Node Verification & Decision orchestrator/verifier.ts  |  orchestrator/retry-policy.ts  |  orchestrator/handoff.ts
Stage 1: Programmatic Verification

Fast checks:
• BLOCKED_MARKERS — captcha, forbidden, access denied, timeout

Retry Policy

Orchestrator Phase 7 — Cross-Node Handoff & Final Aggregation orchestrator/handoff.ts  |  orchestrator/index.ts :: sendTerminationCompletion()
Between Nodes
buildExecutorInstruction() — Next Node Context
Each node receives:
1. buildCompletedStepsSummary(completedNodes) — what prior nodes achieved
2. formatPlannerReflexionContext(reflexionLog) — failures + lessons
3. buildAssumptionDriftSignal(assumptions, currentPage) — planner assumptions vs. reality
4. compactExecutorSummaryForNode() — compact prior node results
5. buildVerifierContext() — verifier findings for retried nodes
6. buildExecutorParallelContext() — sibling worker summaries (parallel mode)
7. Structured progress — reviewed items, extracted facts, outstanding questions
Max handoff depth: 2 (prevents infinite reroute chains). Artifacts capped at 4 per node.

The "Plugin" — 31 Skills × 3 Packs
Skill Catalog + Execution Contracts
Each skill is a self-contained workflow with procedure steps, tool discipline, evidence requirements, and common failure recovery. Packs gate activation based on evidence strength.

The Full Loop
A WorkArena Run
1. workarena-doctor — verify Python, HF token, dependencies
2. workarena-suite — select tasks, seeds, categories
3. workarena-handoff (per task):
4.   Start session-bridge.py (long-lived Python process)
5.   reset → BrowserGym creates task, keeps env alive
6.   export_session → cookies + storage → JSON
7.   importPlaywrightStorageState() → inject into extension Chrome
8.   sendUserChat(goal) → orchestrator runs full pipeline
9.   Orchestrator: plan → skill selected from catalog → execute → verify → done
10.   validate → WorkArena scorer checks task state
11.   teardown → destroy BrowserGym env
12. workarena-grade — aggregate JSON reports → pass@1 scorecard
