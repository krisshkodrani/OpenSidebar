Failure Investigation

How to investigate one failure without losing the fleet

The viewer should keep users in a productive loop: choose a meaningful pattern, inspect one trace deeply, identify the harness layer, and measure whether the fix changed the aggregate behavior.

1

Metric Signal

Look for movement in success rate, tokens, latency, cost, or tool failure rate.

2

Pattern

Use Insights or Ratchet to avoid chasing a one-off trace too early.

3

Sample Trace

Open a representative session and read the evidence turn by turn.

4

Layer

Name the fix layer before editing: tool, skill, policy, verifier, prompt, or context.

5

Ratchet

Copy the brief, implement the fix, and watch the aggregate pattern after reindex.

Investigation Checklist

  • Start from Metrics when the question is performance, cost, latency, or volume.
  • Start from Ratchet when the question is repeated failure and harness improvement.
  • Use sample-session links to validate the pattern against concrete evidence.
  • Reject fixes that only make one fixture pass but do not address the repeated behavior.
  • After the fix, rebuild the SQLite index and compare the same metric again.

Decision Rule

If the trace is confusing but the fleet is clean, keep investigating locally. If the same signature repeats across the fleet, create a ratchet candidate and treat it as harness work.

Evidence first. Layer second. Blame the model last.

Failure Layer Map

Layer Typical Signal Likely Fix
Tool Repeated failed calls for one primitive. Improve the primitive, controller, selector policy, or result validation.
Skill Workflow succeeds manually but the agent misses stable sequencing. Add reusable sequencing and evidence expectations.
Policy Many max-turn or stopped sessions in the same shape. Adjust planning, continuation, recovery, or decomposition rules.
Verifier Agent claims success but trace evidence is weak or contradictory. Add stricter act-check-act verification or failure admission.
Context High utilization, dropped messages, or noisy tool output. Improve compaction, progressive disclosure, or output offloading.
